# UI SYSTEM V1 — BriefProof

## Design Intent

BriefProof should look like a refined modern product review tool, not a crypto exchange and not a generic AI dashboard.

The reviewer should understand the product visually before reading long documentation.

## Visual Direction

Use:
- bright/light interface
- generous whitespace
- strong typography
- crisp borders
- subtle depth
- editorial/product-design feel
- large visual artifact preview
- highly legible acceptance matrix
- restrained motion
- responsive desktop/mobile layout

Avoid:
- black/gold theme
- cyberpunk
- neon gradients
- trading-terminal UI
- excessive glassmorphism
- wallet-first crypto styling
- dense dashboard grids
- cartoonish rounded-everything look
- decorative Web3 clutter

## Information Hierarchy

Primary:
1. visual artifact
2. final verdict
3. acceptance matrix

Secondary:
- brief
- criteria metadata
- creator/review metadata
- hashes and technical verification

Technical chain metadata should be accessible but must not dominate the first screen.

## Home Hero

Should communicate approximately:

**Did the deliverable actually match the brief?**

Supporting concept:

BriefProof turns visual acceptance criteria into a consensus-backed GenLayer result.

Do not use exaggerated marketing claims such as "trustless truth" or "perfect AI judgment".

## Review Detail Layout

Desktop preference:
- artifact preview on one side
- verdict + matrix on the other
- brief and technical evidence below

Mobile:
- artifact first
- verdict second
- matrix third

## Verdict Presentation

Make final state visually unmistakable, but do not rely on color alone.

Use text + icon/symbol + label.

## Criteria Presentation

MUST and SHOULD must be visibly distinguishable.

BINARY/GRADED metadata should remain secondary.

## Loading / Consensus State

Use a calm progress treatment.

Do not fake individual validator votes unless real transaction data exposes them.

Never display invented validator identities/counts.

## Accessibility

- keyboard-accessible controls
- visible focus states
- semantic labels
- sufficient contrast
- meaningful alt text for UI icons
- artifact image alt derived from title, not hidden AI interpretation

## Scope

No custom illustration system is required in Phase 3.
No heavy animation framework is required.
No design-system dependency is required unless demonstrably necessary.
